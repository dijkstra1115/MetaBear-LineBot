# 對話紀錄與常見問題知識庫

從 migration 0007 與新版 Worker 上線後開始記錄。後台客戶詳情可查看用戶文字、選單操作、Bot 回覆、VIP 邀請及 CRM 推播，每頁 50 筆，保留 90 天。排程分批清除到期紀錄；介面立即排除已到期資料。

「LINE 已接受」代表 API 接受傳送，不代表已讀或加入社群。傳送失敗與結果未確認會分開顯示，重送同一事件不重複建立紀錄。驗證碼、後台綁定指令與可辨識憑證會遮蔽；無法保證辨識任意格式的敏感資訊。登入 OTP 不納入一般對話紀錄。

LINE 不提供取回既有文字訊息的 API，因此無法補回上線前對話。用戶附件只記錄類型，客服仍至 LINE 官方帳號查看；官方帳號管理介面由真人手動發出的訊息，也不會自動同步到本系統。收到收回事件後移除對應原文，包含事件順序顛倒的情況。

後台「常見問題知識庫」可新增、編輯、發布或退回草稿。每則有問題、關鍵詞、解法、是否需人工核實、發布依據及版本。從用戶訊息可建立問題草稿；不會自動學習或直接發布用戶提供的答案。最多 100 則；發布前需填寫依據，應由團隊核對平台政策是否仍有效。版本檢查防止兩個編輯者互相覆蓋。

Bot 先比對常見問題與明確教學指令，必要時由 OpenAI 從已發布內容選擇適用解法。模型會參考該用戶最近 24 小時內最多 6 則文字訊息（每則最多 800 字），不送出 LINE 使用者 ID；模型僅選擇主題，回覆由已發布解法產生。草稿及已退回的解法不會使用。系統沒有讓模型自行更改推薦歸屬或核實 VIP 資格的功能。

需要核實的解法會先回答問題，僅在首次將用戶加入需協助名單時附上標記提示。後續追問繼續回答，不反覆提示標記。明確要求「人工協助」時，標記或告知現有需求仍保留。此版本沒有客服即時通知、人工認領或自動暫停 AI；「需協助」不表示真人已讀或接手。

部署順序：先套用 `0007_conversations_knowledge.sql`，再部署 Worker 及 public 資產。初始五則問題包含其他人的邀請碼、變更推薦歸屬、漏填邀請碼、入金後未收到邀請、人工协助流程。推薦歸屬變更均要求依交易所當前規則核實，不承諾可變更。
