# 滑價

名詞圖解 05 · 30 秒 · 桌面本地審核版 · 2026-09-24

目標：看同樣 30 隻市價買單，如何因低價掛賣不足而走過多個價位，讓成交均價偏離下單時的預期基準。

## 分鏡

| 時間     | 主畫面                                               | 一句提示                       |
| -------- | ---------------------------------------------------- | ------------------------------ |
| 0–5 秒   | 相同買入需求、101 起始最優賣價，兩種深度並列         | 同樣買 30 隻，價格會一樣嗎？   |
| 5–11 秒  | 靠近深簿，101 的 40 足以承接 30                      | 30 隻，都在 101 元成交。       |
| 11–23 秒 | 靠近淺簿，5@101、15@102、10@104 依序成交；103 是空層 | 103 元沒掛單，接著買到 104。   |
| 23–30 秒 | 回到結果，均價 101.00 對比 102.50，浮現每隻 +1.50    | 這段成交價差，就是本例的滑價。 |

## 資料與假設

- MetaBear 熊、元、隻為合成教材。左右為兩次獨立模擬，唯一改變是可見賣方深度。
- 起始最優賣價都為 101 元；本例明確以「送單前最優賣價」作預期基準，不與買賣價差或手續費混用。
- 深簿 101/102/103/104 元掛賣分別 40/25/25/30 隻；淺簿分別 5/15/0/20 隻。相同量尺：40 隻對應 240 SVG 單位。
- 深簿買 30：30×101＝3030，均價 101，滑價 0。
- 淺簿買 30：5×101＋15×102＋10×104＝3075；均價 102.50；對基準的每隻差額 1.50，30 隻共多付 45 元。
- 撮合由 `Market.execute` 計算；每個成交事件後均價才改變。不存在 103 元成交，移動軌跡也不新增成交。
- 本課限定靜態簿深度造成的不利滑價，無手續費、延遲期間價格變化或其他新增撤單。不暗示所有滑價都由薄簿造成，也不暗示滑價只可能不利。
- 不展開真實交易所價格保護、IOC、估值基準差異；教材不代表真實下單一定能成交全部。

## 定義來源

2026-09-24 核對 [Coinbase Help：What is slippage?](https://help.coinbase.com/en/coinbase/trading-and-funding/advanced-trade/slippage)：滑價是預期與實際執行價格差，流動性會影響它。另核對 [Coinbase Exchange Trading Rules](https://www.coinbase.com/legal/trading_rules) 1.41–1.43、1.71–1.72：市價依當時可用掛單及價格優先順序撮合，可能跨多個價位。定義為一般機制，教材不套用該平台的全部保護規則。

## 驗收

- 精確交易量、金額、均價與 1.50 差額；103 空層不產生成交。
- 所有事件邊界、反向回拖、數量守恆、殘量非負及有限鏡頭幾何均受測試。
- 開場與結尾同一宏觀空間，放大前後保留深淺簿位置；數據不依動畫速度內插。
- 測試：`tests/orderflow-slippage.test.mjs`。主 Agent 統一整合導航與瀏覽器驗收；不部署。
