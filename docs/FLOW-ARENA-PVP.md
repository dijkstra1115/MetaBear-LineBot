# FLOW ARENA 對戰版

狀態：開房對戰（第二階段）已實作並部署到 `preview.metabear.io`，入口是挑戰頁（`/orderflow/challenge.html`）標題列的「👥 好友對戰」；公開配對（第三階段）尚未實作。單機版規則見 `CHALLENGE-ARENA.md`，本文只寫對戰版不同或新增的部分。

本機測試：`wrangler dev --env staging --local --port 8787`（需要 Node 22），開啟 `http://localhost:8787/orderflow/challenge.html`。同一個瀏覽器的分頁共用同一個玩家身分，要模擬兩位玩家，可以一個分頁用 `localhost`、另一個用 `127.0.0.1`。

## 目標

2–4 名玩家在同一個模擬 BTC 永續市場裡同時交易。每個人都在獵散戶的強平帶，同時自己的強平價也公開在別人的熱圖上：你是獵人，也是獵物。題材參考 Hyperliquid——鏈上倉位與強平價公開，巨鯨的強平價曾被全市場看到並聯手推爆。

錢主要仍從 NPC 市場（散戶強平、造市商）賺來，玩家之間的互動是變數而不是零和。

## 一局的流程

1. **進場**：開房（房號或連結）或加入公開配對。
2. **大廳**：顯示房內玩家名稱與準備狀態。房主可在人數 ≥ 2 時開始；公開配對依配對規則自動開始。
3. **倒數**：伺服器產生種子並模擬開局前 150 秒歷史，倒數 3 秒後開盤。
4. **交易 120 秒**：固定 1× 速度，不能暫停、不能加速。
5. **結算**：所有未平倉部位按簿面平倉，顯示排名、對戰紀錄與盤後揭曉。可一鍵「同房再來一局」。

## 房間與配對

### 開房

- 房號 6 碼（去掉易混淆字元 0/O、1/I），連結 `/orderflow/challenge.html?room=XXXXXX`，房間視窗有「複製邀請連結」和「分享到 LINE」。第一次打開邀請連結的人會先被要求輸入名字。舊的 `/orderflow/arena.html?room=…` 連結會轉到挑戰頁。
- 對戰用的是挑戰頁原本的完整介面（縮放拖曳圖表、音效、連擊特效、Footprint、委託簿、結算複盤）；進入房間後，新市場、每日市場、電腦對手、速度與暫停這些單機功能會隱藏，成績也不存成本機紀錄。
- 房主可以加入新手／中階／高手電腦補位（最多 4 個座位），至少 2 個座位才能開始。
- 開局後不能中途加入。斷線（包括重新整理頁面）不會失去座位或房主身分；按「離開房間」才會讓出座位。房主離線時，第一位在線的玩家可以代為開局；開局時不在線的玩家不會加入這一局。

### 公開配對

- 玩家按「找對手」進入佇列；伺服器依到達順序湊房。
- 規則：湊滿 4 人立即開局；湊到 2–3 人後再等 20 秒，時間到就開局；只有 1 人等滿 30 秒時，詢問要不要改打電腦。
- 同一玩家同時只能在一個佇列或房間；重複進入會取代舊的排隊。
- 公開配對顯示名稱經過長度（≤ 18 字）與保留字過濾；結算頁提供「檢舉名稱」，檢舉達門檻後該名稱在公開配對中改顯示為「交易者 #xxxx」。

### 身分

- 不綁定帳號。網站的登入只給管理員與分析師，對戰版使用匿名玩家身分：第一次進場時伺服器發一組隨機玩家 token 存在 localStorage，用於斷線重連與結果歸戶；顯示名稱沿用單機版的「分享名稱」。

## 市場

- 標的、撮合、NPC 與單機版相同：BTC/USDT 永續，1 單位＝50 BTC，每人起始資金 500,000,000 USDT，槓桿與風險限額相同。
- **規模依人數放大**：2、3、4 人時，每單位合約分別代表 75、100、125 BTC（單機 50 BTC），NPC 的量以 BTC 計跟著放大 1.5／2／2.5 倍，價格行為與單機版相同。每人起始資金與風險限額不變，所以單一玩家的推價力道約為單機版的 1/1.5～1/2.5；幾位玩家合起來推的力道會超過單機版。已在第一階段實作（`ARENA_MARKET_SCALE`）。
- 種子由伺服器產生，結算後公開；同一房間的「再來一局」換新種子。
- 快訊、群聚開倉、獵手、護盤者、大戶照常運作。**獵手會把任何一位玩家的強平價列為目標**（條件與單機版相同：部位 ≥ 1,500 BTC 且強平價在 2.2% 內，或部位 ≥ 4,000 BTC）。

## 資訊透明度

| 資訊 | 自己 | 對手 |
| --- | --- | --- |
| 強平價 | 圖上「你的強平」線 | 熱圖上每位對手一條細線，用對手專用色（不標名字、不標部位大小） |
| 部位、進場價、損益 | 看得到 | 看不到（結算後揭曉） |
| 掛單 | 「你的掛單」列表與圖上標籤 | 只是盤口上的普通掛單，無法分辨是誰的 |
| 成交紀錄 | 自己的成交標 ◆ | 不顯示身分 |
| 爆倉跑馬燈 | — | 對手被強平時顯示「一名玩家的多單／空單被強平 X BTC」，不標名字 |
| 燃料雷達、熱圖亮帶 | 只統計 NPC 散戶；玩家強平價另以細線顯示，不計入亮帶量 |

強平價是公開的，部位大小不是：看到一條對手強平線，要自己判斷值不值得推、會不會有別人一起推。

## 下單與成交

- 所有下單都送到伺服器，按到達順序即時撮合，推價立刻引爆，手感與單機版相同。
- 玩家之間可以互相成交：A 的市價單吃到 B 的掛單，就是 A 與 B 的交易，雙方各自計入損益。
- **自成交防護**：同一玩家的市價或限價單碰到自己的反向掛單時，撤掉自己被碰到的掛單（等同交易所的 expire maker），不會自己跟自己成交。單機版一併改用相同規則。
- 每位玩家每秒最多 10 個指令（下單、撤單、平倉合計），超過的指令會被拒絕並提示。
- 保證金、風險限額、逐倉強平、止損止盈、只減倉等規則都由伺服器逐人計算，與單機版相同。

## 計分與結算

- 得分公式與單機版相同：`max(0, 淨報酬率 %) × max(0, 1 − 最大回撤率 / 20%) × 100`。依得分排名；得分相同時比淨報酬率，再相同則並列。
- 結算頁除了單機版的教練筆記、持倉紀錄與盤後揭曉，另外加上：
  - **排名表**：名次、名稱、得分、淨報酬、最大回撤、被強平次數。
  - **對戰紀錄**：「你引爆了誰」（對手的強平發生在你推價後 3 秒內，歸功於你）、「誰吃了你的出場單」（玩家之間成交的量與對應損益）、被獵手盯上的次數。
  - **全員揭曉**：每位玩家的持倉時間軸與強平價變化。
- 對戰結果寫入 D1（房間、種子、玩家、得分、每位玩家的操作紀錄），可重播與驗證。暫不做排行榜。

## 斷線與提早離場

- 斷線或提早離場都視為「不再下指令」：部位與掛單保留，伺服器照常檢查止損止盈與強平，不會自動平倉，收盤時與其他人一樣按簿面平倉並計入排名。沒有投降或提早結算。
- 玩家用同一個 token 重連，恢復畫面與帳戶狀態，可繼續交易到收盤。
- 所有玩家都離開時市場照常跑完並結算。
- 不提供觀戰。

## 對戰電腦

- 策略在 `public/orderflow/flow-arena-bots.js`（策略實驗腳本也用同一份），每位電腦有名字、難度與槓桿；陣容見 `CHALLENGE-ARENA.md` 的〈對戰電腦〉。新手用高槓桿、抱單不停損，強平價常在射程內，是被獵的對象；高手用 3× 大部位，強平價遠在畫面外。

- 電腦與真人一樣只能看公開資訊，走同一個下單介面與風險限額。
- 對戰電腦先在單機版推出（不需連線），也用來補滿公開配對與房間的空位。

## 技術架構

實作採 **lockstep（鎖步同步）**，而不是伺服器傳送畫面快照：引擎是確定性的（同一個種子、同一串指令，一定得到同一個市場），所以房間只需要轉發指令和時鐘，每個瀏覽器自己跑同一份引擎。

- **共用引擎**：`flow-arena-engine.js` 是多帳戶的；房間裡每個座位是一個交易者，座位順序在所有副本中一致。`you` 參數只決定畫面從誰的角度呈現，不影響市場。
- **協定**（`public/orderflow/arena-protocol.js`，房間與瀏覽器共用）：驗證並正規化交易指令（下單、平倉、平一半、撤單、全部撤單、改槓桿、止損止盈），不合法的指令一律丟棄。
- **房間**（`src/arena-room.js` 的房間邏輯＋`src/arena.ts` 的 Durable Object `ArenaRoom`）：
  - 每個房號一個 Durable Object，路由 `/arena/ws?room=XXXXXX`（`src/index.ts` 與 `src/preview.ts` 都有）。WebSocket 用 hibernation API，閒置的大廳不計執行時間；座位存在 Durable Object 的儲存空間，睡著後醒來能還原。
  - 開局時房間產生種子，自己也跑一份引擎：玩家的指令先在房間的副本上執行，成功才蓋上序號轉發給所有人，失敗只回給送出的人；電腦座位只在房間這一份上決策，它們的指令同樣轉發。
  - 3 秒倒數後每秒一次：電腦先行動，房間 tick，再通知所有人 tick。每 10 秒送一次市場指紋（checksum），瀏覽器比對不一致會提示重新整理。
  - 每位玩家每秒最多 10 個指令。
- **瀏覽器**（`public/orderflow/arena-replica.js`、`arena-online.js`、`challenge.js`）：只依房間送來的順序套用指令和 tick，自己的單也要等房間回傳才生效。中途重連時，房間送來整局的指令紀錄，瀏覽器從種子重播到現在。
- **伺服器權威**：成績以房間那一份引擎為準；目前還沒有寫入 D1（staging 環境沒有資料庫）。

## Cloudflare 免費方案評估

資料來源：Cloudflare 官方文件 [Durable Objects pricing](https://developers.cloudflare.com/durable-objects/platform/pricing/)、[Durable Objects limits](https://developers.cloudflare.com/durable-objects/platform/limits/)、[Workers limits](https://developers.cloudflare.com/workers/platform/limits/)（2026-09 查閱）。

- **Workers Free 可以用 Durable Objects，但只能用 SQLite 儲存後端。** `wrangler.jsonc` 的 migration 要用 `new_sqlite_classes`，不能用舊的 key-value 後端。
- 免費額度（每日，UTC 午夜重置）：請求 100,000 次、執行時間 13,000 GB-s，SQLite 儲存全帳號 5 GB。
- 收到的 WebSocket 訊息以 20:1 計為請求（100 則訊息算 5 次請求）；送出的訊息不計請求。
- 每次請求 CPU 上限 30 秒（Durable Objects，兩種方案相同）；一般 Worker 在免費方案是每次 10 ms，所以撮合與 tick 必須在 Durable Object 裡跑，不能放在一般 Worker。

**一局的用量估算：**

| 項目 | 估算 |
| --- | --- |
| 房間存活時間 | 大廳 + 倒數 + 120 秒 + 結算 ≈ 200 秒；每秒 tick 期間無法休眠，全程計時 |
| 執行時間 | 128 MB × 200 秒 ≈ 25 GB-s |
| 請求 | 4 條連線 + 玩家指令（每人約 100 則 ÷ 20）≈ 25 次；若 tick 用 alarm 驅動，每秒另計 1 次，約 +120 |
| CPU | 單機實測一整局（含 150 秒暖盤）約 15 ms，放大 4 倍市場後仍遠低於上限 |

以執行時間為瓶頸，**免費額度約可支撐每天 500 局**（請求額度約 700 局）。公開配對的 `Matchmaker` 用 WebSocket Hibernation，排隊時幾乎不計執行時間。

注意：
- 請求額度與網站其他 Worker（LINE Bot、後台）共用每日 100,000 次；對戰量大時要一併觀察。
- 超過免費額度時，當天的新請求會失敗，直到 UTC 午夜重置。上線時要在大廳顯示「伺服器忙碌，請稍後再試」而不是直接壞掉。
- 若之後改用 Workers Paid（每月 5 美元起），每月含 100 萬次請求與 40 萬 GB-s，約 16,000 局。
