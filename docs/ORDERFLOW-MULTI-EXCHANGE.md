# 訂單流平台：多交易所與全市場（2026-10-25）

訂單流網頁目前可以在 Bybit 和幣安之間切換。這份計畫再加入 OKX 和 BingX，並新增「全市場」模式，把四家合在一起看。全市場是平台之後的主要畫面。

## 決定

- **全市場為主**：觀眾大多是從 LINE 社群進來的新手，不會自己切換交易所，預設畫面就是他們眼中的「市場」。單一交易所的大單和 CVD 雜訊較多，合併後只有多家同時發生的事會明顯。進階使用者可以切到單一交易所，網頁會記住選擇。
- **預設是全市場**：上線前先補齊歷史：幣安與 OKX 用每日封存檔補 30 天，Bybit 原本就有。BingX 沒有封存檔，從 2026-10-25 開始累積，它的成交量只占四家的一小部分。曾經選過交易所的人維持自己的選擇（`metabear-orderflow-ex`）。
- **價格以幣安為準**：各家價格差幾美元，把成交混在一起會畫出假的影線。所以 K 線的開高低收用幣安；成交量、Delta、CVD、足跡、OI、爆倉則四家加總。畫面要標示「價格以幣安為準，成交量為四家合計」。
- **掛單熱力圖用幣安**：各家掛單深度的範圍不同，加總會誤導。
- **大單不分顏色**：圖上維持綠買、橘賣兩色；同一根 K 棒同方向合成一顆泡泡（`mergePrints`），所以泡泡數量不會變多，只是變大。哪一家的明細放在 K 棒卡片裡。全市場的大單比單家多，上線後依畫面調整預設門檻。
- **跨交易所同時大單**（第二步）：幾秒內有兩家以上同方向大單時加外框標示，並寫進旁白。
- **BingX**：社群的推薦獎勵在 BingX，觀眾可能實際在那裡下單，所以即使成交量較小也加入。

## 連線

2026-10-25 實測：OKX 和 BingX 的 REST 與 WebSocket 從 Cloudflare 都連得到（連美國機房 SJC 都可以），所以這兩家和 Bybit 一樣由 Durable Object 直接連線，不需要經過東京中繼。BingX 的 WebSocket 訊息是 gzip 壓縮的二進位資料，要先用 `DecompressionStream` 解壓。

| 交易所 | 收集器 | 連線 | 單位換算 | 歷史足跡 |
| --- | --- | --- | --- | --- |
| Bybit | `Collector` | DO 直連 | — | 每日封存檔（已自動） |
| 幣安 | `BinanceCollector` | 東京中繼 | — | `data.binance.vision` 每日 aggTrades zip（Cloudflare 下載得到，只有即時 API 被擋） |
| OKX | `OkxCollector` | DO 直連 | 一張合約 0.01 BTC | `static.okx.com` 每日成交 zip（以北京時間分日，從 UTC 16:00 開始） |
| BingX | `BingxCollector` | DO 直連 | 數量已是 BTC；OI 是 USDT 金額 | 沒有公開封存檔，從上線日開始累積 |

收集器每天自己匯入前一天的封存檔：Bybit 是 gzip，幣安與 OKX 是 zip，在 Worker 裡整個下載後用 `deflate-raw` 串流解壓（`collector.ts` 的 `zipEntry`），OKX 以 `archiveOffset` −8 小時對齊北京時間的日子。更早的日子用 `npm run lab:orderflow:archive -- --ex binance|okx --days 30 --api …` 補。2026-10-25 本機實測：OKX 一天 201 萬筆成交，Worker 匯入和腳本匯入得到相同的 1,440 根 K 棒與 5,615 筆大單。

共用的部分在 `direct-collector.ts`（OKX、BingX 的連線、心跳、沉默重連與大單合併）；BingX 的 OI 是 USDT 金額，以標記價格換算成 BTC。

## 全市場的計算

由 Worker 在回應 `?ex=all` 時把各收集器同一個時段的資料合起來，不另外儲存：

- **K 棒**：開高低收取幣安的；幣安沒有的分鐘依序改用 Bybit、OKX。各價位的主動買賣量四家相加。
- **大單**：四家合在一起，每筆多帶一個交易所欄位（`[t, side, price, qty, ex]`），網頁卡片用它列明細。
- **OI**：換算成 BTC 後相加，USDT 金額也相加；只加總整段時間都有紀錄的交易所（第一筆讀數在起點後 5 分鐘內），否則某家歷史開始的那一刻會出現台階。BingX 沒有 OI 歷史，所以要等它累積滿查詢的時段才會算進去。
- **資金費率**：取幣安的。**多空比、大戶持倉比**：取幣安的。
- **爆倉**：每個收集器只取自己交易所的紀錄（Bybit 的收集器也記了 OKX，不能重複算）。
- **熱力圖、細掛單簿**：幣安的。
- **事件與旁白**：先用幣安收集器的事件；全市場資料上的事件偵測是後續工作。

網頁即時部分：全市場模式連四家的成交串流（流量小），掛單串流只連幣安；幣安的成交決定 K 棒價格，其他三家只加成交量（`app.js` 的 `onTrade(tr, priced)`）。全市場不顯示即時 OI，正在形成的 K 棒 OI 等收集器的讀數。K 棒卡片多一列「來自」，列出各交易所的大單筆數與數量。

## 階段

1. 幣安封存檔補資料（2026-10-25 已匯入 9/25–10/24 到正式環境）。
2. OKX 收集器（完成）。
3. BingX 收集器（完成）。
4. 全市場 API（`?ex=all`）與網頁選項、K 棒卡片的各交易所大單明細（完成）。
5. 部署：`npm run orderflow:deploy`（套用 `v3` 遷移，建立 OKX 與 BingX 收集器），再用腳本補 OKX 30 天，最後 push `main` 發布網頁。
6. 之後：跨交易所同時大單、依全市場的畫面調整大單門檻、全市場事件偵測。
