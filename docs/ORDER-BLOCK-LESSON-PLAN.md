# 訂單塊：大買家如何留下起漲區

2026-09-24 依本地審核重製。40 秒、桌面版、原生 JavaScript／SVG；保留宏觀進場，重新製作中段形成機制。課名仍為「訂單塊到底長怎樣？」。

## 一個核心問題

**大買家在買，為什麼先留下一根收跌 K？**

A 想完成 80 隻買入。先以限價單承接主動賣出，控制願付價格；成交價從 103 向下走，A 的買入量反而增加。期限接近時，A 還差 30 隻，改為主動買入；此刻賣單每檔只有 5 隻，逐檔成交才把價格推到 107。最後返回原全景，把位移前的承接位置保留為本例的訂單塊區域。

這是具名角色與執行目標已知的合成案例。它示範一種能形成該圖形的機制，不將 K 線形狀直接當成機構身分或操縱意圖的證據。畫面只短標「一種形成情境」，不反覆加入方向警語。

## 研究結果與來源

1. [BIS Markets Committee：FX execution algorithms and market functioning（2020）](https://www.bis.org/publications/fx-execution-algorithms-and-market-functioning.pdf)，印刷頁 10、19–21、50、53。拆單與被動等待涉及成本、等待風險、完成確定性的取捨；混合執行可以依時間或價格條件切換為掃單。支持本例「先等、後為完成剩餘需求而主動成交」的動機；報告沒有把此流程稱為 OB，也沒有證實所有 OB 都來自同一機構。
2. [CME：Liquidity Tool Methodology](https://www.cmegroup.com/education/articles-and-reports/understanding-the-cme-liquidity-tool-methodology)。委託簿隨新增、成交與撤單更新；最佳賣價數量不足，買入成本計算需使用後續賣價檔。本課每一次上移都由實際成交產生。
3. [ICT 官方：2016 Mentorship Core Content — Month 04 — Orderblocks](https://www.youtube.com/watch?v=PIYh0CxoY9c&t=60s)。研究核對約 1–2 分鐘的原始投影片：看漲 OB 包含支撐附近較低位置的收跌 K 與較大的開收範圍；投影片以後續成交穿越該 K 高點確認。核對範圍是原投影片，未取得可核驗的完整口述字幕；不引用二手網站的「刻意壓價」說法作為原話。
4. [LuxAlgo：Order Block Anatomy & Refinement](https://www.luxalgo.com/library/concept/order-block-anatomy-and-refinement/)。其公開現代畫法從位移回找最後反向 K，並說明整根高低、實體等不同邊界，以及結構突破等篩選方式。本課選「最後收跌 K＋後續收盤越過既有前高＋整根高低」，屬明訂的教學篩選規則，並非原始 ICT 定義的逐條複製。

「莊家為什麼這樣」在這堂課落成可演示的執行問題：大額需求需要對手方，成交價格與完成速度有取捨。A 全程只買未賣；沒有演成他先賣出壓價、誘騙其他人，再抬高自己庫存。

價格重返 OB、原始未成交單仍在、同一機構防守成本區，是三個不同命題。此研究沒有建立它們的必然連結；本課不增添沒有委託與身分資料的回訪／防守故事。上方深度是下一分鐘的明示賣單快照，不宣稱它因上一分鐘承接而自動變薄。
