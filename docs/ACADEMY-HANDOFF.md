## 不可丟掉的設計判斷

- 每課只回答一個問題，不重述前置課程；自由選看，故事只附前置概念連結。
- 名詞圖解用簡短確定的名詞；市場故事可用具體疑問句。
- 新圖解通常約 30 秒，故事約 30–40 秒。節奏偏俐落，不加片頭、冗長停留與解說段落。
- 深墨底、低對比格線、薄荷綠、暖金、米白；留白、克制高亮、清楚文字階層。沿用目前成品比例，不另做一套儀表板美術。
- 全景建立空間 → 放大同一場景的局部 → 真正發生交易／數據變化 → 縮回保留結果的全景。鏡頭必須幫助理解，物件位置與歷史保持連續，不是投影片切換加縮放特效。
- 市場故事先用多根 K 快速提出問題，zoom in 時明示選段回看。既有背景 OHLC 可合成，回看前後須一致；合併課開場只顯示六根已完成 K，後三根隨事件形成，退鏡保留新增歷史。不要提前洩漏尚未發生的成交，也不要改回開場單根 K 或直接並排資料表。
- 元素隨故事逐步登場，每個節拍只強調一件事。讓學員看見因果，而不是讀長篇說明。
- 底部固定一句短字幕，通常 10–22 字；動畫能說清楚的就刪掉重複文字。
- 最新偏好：直接描述畫面事實，不反覆補「不代表之後會漲」「不保證未來方向」。必要的口徑用簡短圖例，研究邊界放課程文件；同時不要做超過畫面證據的推論。
- 畫面中同時有委託簿與 K 線時，成交位置與 K 線同步；撤單只改深度，不能自己推動最新成交價。
- 比較兩種機制時，先完整演出第一種，明示回到同一起點再演第二種；最後才短暫並排結果。
- 自動連續播放、暫停、回拖、跳幕、重播皆要成立。完成時停在結果，支援減少動態偏好。

## 實作與分工

沿用原生 JavaScript、SVG、`story-player.js` 的 `mountStory`。不要換框架、改做影片或重建整個網站。每課沿用現有五檔架構：

`public/orderflow/<id>.html`、`<id>.js`、`<id>-model.js`、`<id>-view.js`、`<id>-script.js`。

配套新增 `docs/<NAME>-LESSON-PLAN.md` 與 `tests/orderflow-<id>.test.mjs`。課程卡記錄一句目標、分鏡、數字假設、可靠來源及驗收結果。

- model 由 playhead 純函式重建事件與統計；數字只在實際事件時改變，正反回拖不能洩漏未來資料或累加副作用。
- view 負責鏡頭與 SVG；script 負責幕名、時間點及短字幕。動態可平滑，成交數字不可插值捏造。
- 匯出 `SCENE_DURATIONS`、`SCENE_STARTS`、`TOTAL_DURATION`、`scenePosition`、`scenes`、`narrativeAt`，沿用 `continuousDesktop: true` 與既有完成狀態。
- 共用 `wick.css`、`primer-desktop.css`；body 設自己的 `data-chapter` 與 `data-lesson-style="compact"`。可用既有撮合引擎，不為新課改寫共用撮合規則，也不要匯入另一課模型充當新模型。
- Agent 只改自己課程的五檔、課程卡與測試。主 Agent 統一修改 catalog、導覽、播放器／共用 CSS、README 與課程架構；避免共享檔案互相覆寫。
- 主 Agent 必須親自用瀏覽器看成品與修細節，不能只採信子 Agent 的「完成」或測試通過。只讓一個 Agent 操作瀏覽器，避免搶同一頁。
- 課程完成後才將 catalog 從 `planned` 改為可觀看並加入正確 href、時長；執行本地建置生成課程地圖與側欄，不手動逐頁改導覽。
