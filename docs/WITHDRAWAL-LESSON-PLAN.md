# 掛單撤走，價格就會上漲嗎？

市場故事 S04 · 35 秒 · 本地桌面審核版 · 2026-09-24

目標：把撤單造成的可成交位置改變，與下一筆交易造成的成交價改變分開觀察。2026-09-24 重修：委託簿中央加入同一根 K 線，直接跟隨真實成交更新。

## 四幕

| 時間     | 演出                                                                                                               |
| -------- | ------------------------------------------------------------------------------------------------------------------ |
| 0–6 秒   | 宏觀看見成交紀錄與同一份委託簿：最新成交 101，最低掛賣 102。                                                       |
| 6–18 秒  | 鏡頭靠近前方掛賣，11 秒撤走 102×25，12.5 秒再撤 103×30；價格 101 與量 5 的固定數字完全不變，刻意保留無成交的片段。 |
| 18–27 秒 | 新的主動買入 5 到場，21.5 秒從現在最接近的掛賣 104 成交；此時才更新成交價 104、量 10，K 線由 101 拉高至 104。      |
| 27–35 秒 | 回到全景，成交記錄顯示先長時間停在 101，再出現 104 的新點。                                                        |

## 假設與資料

- 合成商品 MetaBear 熊；元、隻為教學單位。單一委託簿、單一連續時間軸。
- 原始掛賣 101×5、102×25、103×30、104×40 共 100。開場先前已買入 101 的 5，故開場成交價 101、量 5，掛賣從 102 開始。
- 掛買 100×25、99×20 始終保留。中途只撤掉指定的 55 隻掛賣，不新增、換價或成交。
- 取消後最低可見賣價為 104，但最新成交仍是 101。這區分了報價改變與成交價改變，不宣稱所有「價格」指標都不變。
- 新買單只有 5，直接在 104 成交，不重播大單逐層掃單的滑價課；104 掛賣剩 35。
- `Market.cancel` 與 `Market.execute` 計算帳簿與成交。取消 API 所需 own 屬性只用來指定可取消測試訂單，不是課程中的持有人身分。
- 不推定掛單者身分、操盤意圖、欺騙行為；本例亦不表示撤單之後必然有新買單或必然上漲。畫面採慢放。

## 一手來源

2026-09-24 核對 [Coinbase Exchange Trading Rules](https://www.coinbase.com/legal/trading_rules)：1.24 說明掛在簿上的訂單可在成交前取消；1.41–1.43 及 1.71–1.72 說明新市價單按可用價格與深度撮合；3.12 把訂單取消與成交列為不同市場資料事件。教材的價格／量結論依實際事件逐筆重建，不將撤單當作交易。

## 驗收

- 撤掉 102、103 時交易筆數與成交價／量皆不變，僅最優掛賣改變。
- 21.5 秒前最新成交 101、量 5；當刻才變 104、量 10。
- K 線只使用已發生成交重建：撤單時 OHLC 維持 101；104 成交後變成開／低 101、高／目前收 104。回拖必須還原，不能讓撤單或買單移動預先拉高 K 線。
- 各時點剩餘掛賣＋已撤量＋已成交量＝100。
- 35 秒、可逆回拖、同場景縮放、有限幾何，減少動態模式保留相同資料。
- 對應測試 `tests/orderflow-withdrawal.test.mjs`；主 Agent 統一整合導覽與瀏覽器驗收，不部署。
