# 訂單流平台：加入 ETH（2026-10-27）

ETH 要和 BTC 一樣完整：Binance、Bybit、OKX、BingX 四家加全市場，事件也推到 LINE，會員可以分開選要收 BTC 還是 ETH。

## 決定

- **一份市場設定**：`public/lab/orderflow/markets.js` 列出每個市場的代號、交易所的交易對名稱、價格格距與數量換算，其他程式都從這裡讀，不再寫死 BTC。
- **價格格距**：BTC 足跡每格 $10，約是價格的 0.0125%。ETH 約 $2,300，用每格 $0.5（約 0.02%）。細掛單簿 BTC 每格 $1，ETH 每格 $0.05。
- **數量門檻**：BTC 的門檻以 BTC 計，例如大單 ≥ 2 BTC 才存、LINE 大單 ≥ 50 BTC。ETH 一顆約是 BTC 的 1/35，成交額約是 BTC 的一半，所以 ETH 的門檻是 BTC 的 30 倍，取整數：大單 ≥ 50 ETH 才存、LINE 大單 ≥ 1,500 ETH、跨所同步每家 ≥ 300 ETH、新手版泡泡 ≥ 300 ETH。實際畫面出來再調。
- **金額類門檻不變**：連環爆倉以美元計（$2M）、OI 急變以百分比計，兩個市場共用。
- **收集器**：同樣的 Durable Object 類別，用交易對名稱開不同的物件，例如 `idFromName("ETHUSDT")`。物件第一次被呼叫時，Worker 會告訴它是哪個市場，它會記下來，之後的 alarm 就照這個市場執行。現有的 BTC 物件沒有記錄，一律當作 BTC。
- **API**：`/api/orderflow/ethusdt/*`，和 BTC 的路徑格式相同。
- **東京中繼**：同一支程式同時轉送兩個市場，每個市場各自連一條往 Cloudflare 的連線（`/api/orderflow/relay?m=eth`）。
- **網頁**：標題旁多一個 BTC／ETH 選單，分享連結帶 `m=eth`。
- **LINE**：
  - 推播文字標明市場，例如「MetaBear 訂單流通知（ETH）」，大單寫「ETH」而不是「BTC」。
  - 會員的訂閱多一個「市場」設定：只要 BTC、只要 ETH，或兩個都要。已訂閱的會員維持只收 BTC。
  - 每天則數的上限是兩個市場合計，不會因為多了 ETH 就收到兩倍的通知。
  - 需要一個資料庫遷移（`0018`）替訂閱加上市場欄位。

## 費用

多 5 個常駐收集器，依之前的估算約每月多 $20。東京主機不用換，多轉送一個市場的流量還在額度內。

## 階段

1. 市場設定、收集器與 API 依市場運作（BTC 行為不變，現有測試全部要過）。
2. 東京中繼同時轉送兩個市場。
3. 網頁的市場選單、單位、格距與門檻。
4. ETH 的事件推到 LINE，加上會員的市場訂閱設定與資料庫遷移。
5. 部署：Worker、中繼、CRM 後端與遷移、網頁；用封存檔補 ETH 30 天的歷史。
   - 順序：先套用遷移 `0018` 並部署 CRM 後端，再部署 Worker。舊的後端看不懂事件上的市場，若 Worker 先上線，ETH 事件會被當成 BTC 推給只訂 BTC 的會員。

LINE 關鍵字：沒寫幣種就是 BTC（和 ETH 之前的關鍵字相同），要 ETH 就加上 `ETH` 或 `BTC,ETH`，例如「訂閱警報 BTC,ETH 全部 每天3則」。網頁通知只看目前畫面上的幣種。
